# 制度知识智能服务平台一期UI设计规格

**版本：V1.0**  
**日期：2026-08-23**  
**实现基线：React 18 + TypeScript + Ant Design 5 + Ant Design X 1.6.1**

## 1. 设计目标

界面面向普通员工和制度管理员，风格采用清晰、稳重、低学习成本的企业应用设计。普通员工进入平台
后，应在三个动作内完成“提问”“搜索制度”或“从Citation回到原文”。

设计约束：

- 主要验收尺寸为1440×900，最低浏览器内核Chrome 89；
- 一期以桌面端为主，低于1200px时侧栏变为Drawer，不建设手机专版；
- 通用页面使用AntD，Ant Design X只用于聊天交互区；
- 不展示虚假的制度总数、准确率、用户数、热度和排行榜；
- `ANSWER/INSUFFICIENT_EVIDENCE/CONFLICT`依靠文字、图标和颜色共同区分；
- 页面不得显示服务器绝对路径、模型reasoning、Prompt、密钥或内部异常栈。

## 2. 全局应用框架

```text
┌──────────────────────────────────────────────────────────────┐
│ 平台Logo/名称   首页   智能问答   制度库      服务状态  用户区 │
├──────────────────────────────────────────────────────────────┤
│ 面包屑或页面标题                                               │
│                                                              │
│                         页面内容                              │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

一期无登录时用户区显示“本机试运行”，不伪装真实账号。RAG诊断不出现在普通导航；开发期通过直接路由
访问，二期登录后放入管理员菜单。

全局状态：

- Knowledge Engine可用：绿色圆点和“知识服务正常”；
- Knowledge Engine不可用：黄色/红色状态，问答入口禁用，制度库仍可使用；
- 页面加载：使用`Skeleton/Spin`；
- 空数据：使用`Empty`并给出下一步动作；
- 全局错误：使用`Result`并保留request_id供反馈。

## 3. 首页 `/`

### 3.1 页面结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 制度查询，有依据地回答                                        │
│ 查询当前有效制度，回答可回到原文、条款和页码                    │
│                                                              │
│       [询问制度 | 搜索制度]                                   │
│       [输入问题或制度关键词……                    ] [提交]      │
├────────────────────────────┬─────────────────────────────────┤
│ 常见问题                    │ 最近更新                         │
│ 问题标题                     │ 制度名 / 文号 / 更新时间 / 状态   │
│ 问题说明                     │ 点击进入制度详情                  │
└────────────────────────────┴─────────────────────────────────┘
```

### 3.2 组件与交互

- 主体：`Layout/Typography/Space`；
- 模式切换：`Segmented`；
- 输入：`Input.Search`或`Input + Button`；
- 常见问题：`List`或轻量`Card`；
- 最近更新：`List/Tag`，固定最多5条active制度；
- 服务异常：`Alert`。

“询问制度”提交后创建会话并进入`/chat/:sessionId`；“搜索制度”提交后进入
`/documents?keyword=...`。常见问题由管理员或配置文件维护，不根据虚构热度排序。

## 4. 智能问答 `/chat`、`/chat/:sessionId`

### 4.1 桌面布局

```text
┌──────────────┬──────────────────────────────┬────────────────────┐
│ 会话列表      │ 消息区                        │ Citation证据面板    │
│ 240～280px    │ min-width: 600px             │ 360～420px          │
│ 新建会话       │ 用户/助手Bubble               │ E1、E2               │
│ 搜索会话       │ 三状态提示                     │ 制度/条款/页码/原文   │
│ 最近会话       │ Sender固定在底部               │ 定位正文/打开PDF      │
└──────────────┴──────────────────────────────┴────────────────────┘
```

### 4.2 组件

- 会话：Ant Design X `Conversations`；
- 消息：X `Bubble.List`；
- 输入：X `Sender`；
- 常见问题：X `Prompts`；
- 操作：X `Actions`及AntD `Button/Tooltip/Dropdown`；
- Citation：自研`EvidencePanel`，使用AntD `List/Collapse/Descriptions/Tag/Typography/Drawer`；
- 反馈：`Popover/Modal/Checkbox/Input.TextArea`。

### 4.3 三种答案状态

| 状态 | 主区表现 | 证据区表现 |
|---|---|---|
| `ANSWER` | 正常答案；每项关键结论显示`[E编号]` | 只展示答案实际使用的Citation |
| `INSUFFICIENT_EVIDENCE` | 明确说明资料不足，不输出猜测性具体结论 | 可为空；不得把召回结果伪装成引用 |
| `CONFLICT` | 分别展示不同规定和适用边界 | 按立场分组，每一方都有Citation |

点击`[E1]`时右侧选中E1并滚动到可见位置；点击“定位正文”进入制度详情并定位Node；点击“打开PDF”
进入对应页。复制答案保留E编号。点踩必须选择至少一个原因，可勾选“提交为候选评测案例”。

### 4.4 门禁失败

Generator草稿未通过问答质量门禁时，普通用户只看到`INSUFFICIENT_EVIDENCE`和request_id。不得显示
原草稿。开发人员可在RAG诊断页查看被拦截原因。

2026-08-23测试版质量门禁尚未冻结性能SLA，15题命令P50/P95为`15.018s/25.623s`。M0/M1使用Mock
验证加载状态，不把该数值写死为产品超时：问答发送后持续显示明确的处理中状态，允许用户取消本地
等待；请求是否真正取消由Platform API实现时统一定义。M3联调完成并经过暖态API压测后再冻结超时、
慢请求提示和SLA。

## 5. 制度库 `/documents`

### 5.1 页面结构

```text
制度库
[关键词________________] [状态] [发布机构] [日期区间] [查询] [重置]

制度名称 | 文号 | 发布机构 | 生效日期 | 状态 | 责任部门 | 更新时间 | 操作
--------------------------------------------------------------------
……       | ……   | ……       | ……       | 有效 | ……       | ……       | 查看

                                      分页 / 每页条数
```

### 5.2 规则

- 查询条件写入URL，刷新和复制链接后仍可恢复；
- 关键词覆盖标题、文号、机构和FTS5正文；
- 默认只显示active且现行有效制度；
- 排序默认`updated_at desc`；
- 表格行点击或“查看详情”进入`/documents/:documentId`；
- 无结果时保留查询条件，并提示调整关键词，不自动转成语义问答。

## 6. 制度详情 `/documents/:documentId`

### 6.1 页面结构

```text
制度库 / 制度详情
制度标题
文号 | 发布机构 | 发布/生效日期 | 状态                         [打开PDF]

┌────────────┬────────────────────────────────────┬──────────────┐
│ 目录树      │ 结构化正文                          │ PDF预览      │
│ 220～260px  │ 章节、条款、段落、Node锚点           │ 当前页        │
│ 当前条款高亮 │ Citation目标段落高亮                 │ 新窗口打开    │
└────────────┴────────────────────────────────────┴──────────────┘
```

### 6.2 规则

- 只读取active ParseRun并按`order_no`展示；
- URL接受受控`node`、`page`、`evidence`查询参数；
- Citation进入后，对应Node高亮并显示“来自回答E1”；
- 页面显示条款路径和页码，不显示服务器路径；
- 历史Citation的`parse_run_id`不同于当前active时，顶部显示版本变化提示；
- 普通用户默认查看保存的Citation快照和当前有效制度，不允许冒充查看历史active正文；
- PDF原生内嵌不可用时提供同源新窗口打开。

## 7. PDF查看 `/documents/:documentId/pdf?page=N`

- 页面顶部显示制度名、文号、目标页和“返回制度详情”；
- 后端根据`document_id`解析允许目录中的PDF；
- 浏览器参数不能包含文件绝对路径；
- 页码定位失败时打开PDF首页并提示目标页，不静默显示错误页；
- 不支持内嵌时显示`Result`和“在新窗口打开”。

## 8. 服务说明 `/settings/about`

展示平台版本、知识库最后更新时间、active IndexRun公开版本、Knowledge Engine状态和浏览器基线。
不展示模型服务IP、密钥、容器信息、内部文件路径或reasoning设置。

## 9. RAG诊断 `/diagnostics/requests`

开发期仅本机和显式配置开启，后期只允许管理员访问。

### 9.1 请求列表

- 筛选：request_id、原问题关键词、最终状态、质量门禁状态、是否点踩、日期；
- 列表：时间、问题摘要、状态、Citation数、IndexRun、耗时、反馈；
- 点击进入`/diagnostics/requests/:requestId`。

### 9.2 请求详情

```text
原问题
  ↓
Query Rewrite（原文、重写结果、是否启用）
  ↓
Dense Top20（rank、score、chunk、制度）
  ↓
Rerank Top8（前后rank、score、变化）
  ↓
Context（选中证据、去重、预算、丢弃原因）
  ↓
Generator草稿（严格结构，不展示reasoning）
  ↓
质量门禁（关键结论—E编号、PASS/拦截原因）
  ↓
公开答案和Citation快照
```

## 10. 响应式和可访问性

- 宽度低于1200px：会话列表和Citation侧栏变为Drawer；制度详情目录和PDF区改为Tabs/Drawer；
- 键盘可以依次访问导航、表单、消息操作和Citation；
- 图标按钮必须有文本或`aria-label`；
- 状态不能只靠颜色区分；
- 正文和证据原文允许用户选择复制；
- 表格在窄屏允许横向滚动，不压缩到不可读；
- Chrome 89基线和现代Chrome/Edge均使用生产构建产物执行冒烟。

## 11. 一期UI完成定义

1. 首页的搜索和问答分流正确；
2. 三种问答状态均有稳定页面表现；
3. Citation能从答案跳到证据、Node和PDF；
4. 制度库筛选条件可复制、刷新和恢复；
5. 制度详情只显示active正文，历史Citation显示快照和版本变化提示；
6. 错误、空状态、加载状态和服务不可用状态齐全；
7. 诊断页可定位RAG各阶段，但不泄露reasoning和敏感配置；
8. 1440×900和Chrome 89基线冒烟通过。
