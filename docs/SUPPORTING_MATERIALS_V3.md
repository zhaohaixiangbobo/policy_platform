# 配套资料检索与聊天分流 v3

> 文件说明：2026-10-11，已实施批准的阶段一、二。字段格式仍为 supporting_materials_v2；检索策略升级 material_search_v3，无数据库迁移、无需重新导入。

## 阶段一：主题匹配及片段

推荐从标题、问题性质、图片关键词取得主题，规范全半角、少量问句表达和明确同义表达（中央八项规定精神→八项规定，举报办理→信访举报）。不接模型、不建大词典、不作向量检索。具体领域仅在强主题已匹配时加分，不能独立触发；党纪、处分、其他等泛词不能独立触发。

字段评分：问题性质/关键词10，只有标题匹配8，两者取其一；命中原文连续句加2，领域加1。原文不能独立推荐，同主题不会因标题和标签重复出现而重复加分。同分保留ID稳定排序。仍只读取已发布资料及其发布修订，阈值6，问答每类最多2条，学习每类最多1条。

推荐items新增可选match_reason和match_excerpt。命中句必须来自原文连续句，不拼接不同人员/不同句的事实；240字以内保留整句，超长句回退原文预览。收受礼品礼金允许同一句中的间隔修饰语；不将管理服务对象支付宴请等同公款吃喝。没有文字佐证时显示字段匹配原因和“原文预览”，不假装是相关原文。

独立搜索仍偏召回，保留多关键词、字段检索与筛选；推荐共用同一服务的精确分支。学习评分、生成、权限和制度RAG保持原规则。

## 阶段二：纯资料请求分流

明确案例或流程图请求由Platform资料服务回答，不调用RAG/LLM、不生成制度Citation。reason_code=MATERIAL_SEARCH，answer_status=ANSWER，generator/index等RAG执行字段不伪造。提示为“找到相关资料”或“当前已发布资料未匹配”，卡片仍异步按当前发布状态读取。历史聊天的推荐不是永久快照，资料下架后可消失。

含结合、解释、分析、如何处理、处分、处罚、依据等表达继续制度问答；“流程是什么”不等同“找流程图”。保守规则第一版可能漏分流复杂表达，不能宣称完整意图理解。

“还有相关案例吗”仅继承紧邻完整一轮，制度选择与CURRENT/HISTORICAL一致才继承；明确新主题不沿用。无material.read返回权限提示，SELECTED返回尚未建立关联提示，不扩大到全库。现有聊天入口仍执行制度范围解析；本轮未解除聊天对可查询制度快照的既有前置要求。

## 验证与使用

最小后端：`tests/test_material_search_v3.py`、`tests/test_materials.py`、`tests/test_chat_integration.py`，共21项；覆盖自然问句、泛词、字面片段、同主题去重、纯资料不调用RAG、权限、SELECTED、追问及原聊天回归。测试使用隔离会话，不写真实PG。

真实PG只读复核25条发布资料：三种八项规定问法均匹配2条，公款吃喝0条（不强行扩大），收受礼品礼金1条。不新增/修改案例、标签或发布状态。

前端推荐组件7项定点测试及typecheck通过，build通过（既有大包体积警告）。未执行全量、压力、真实模型调用及浏览器视觉验收。启动使用当前PG配置的 `scripts/dev-postgres.ps1 -Service api`，不要直接使用旧默认SQLite环境脚本。

最小复测：backend目录执行 `& 'D:\3-anaconda\envs\py312\python.exe' -m pytest tests/test_material_search_v3.py tests/test_materials.py tests/test_chat_integration.py -q`；frontend目录执行 `node --test tests/material-recommendation-ui.test.mjs`。本次API测试显式注入隔离配置，不读取迁移前默认.env。OpenAPI已按PG配置重新导出，recommendations可选kind限定类型，防止继承的问题带其他类型意图时扩大展示。

人工验收：输入“有违反八项规定的案例吗”查看资料提示及卡片；输入“违反八项规定如何处理”确认仍走制度问答；再问“还有相关案例吗”检查上下文；换“信访举报流程图”确认不残留旧主题。无关、无权限、指定制度模式不扩大推荐。
