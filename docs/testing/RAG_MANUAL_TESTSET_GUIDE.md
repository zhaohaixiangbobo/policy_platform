## 2. 建议建设的正式测试集体系

同一题只能有一个主用途；同一知识点的改写题必须使用相同的 `paraphrase_group_id`，并整体进入同一数据分区，避免开发集和盲测集互相泄漏。

| 数据分区 | 用途 | 是否允许研发查看答案 | 是否允许用于调优 |
|---|---|---|---|
| DEV | 日常开发、检索和提示词调优 | 允许 | 允许 |
| HOLDOUT | 独立验收和发布门禁 | 只由验收负责人保管 | 禁止 |
| REGRESSION | 已确认的真实失败案例 | 允许 | 允许，但保留首次失败记录 |
| PERF | 暖态响应时间和并发容量 | 允许 | 只固定负载，不评价内容调优 |

首批建议征集 150–180 条员工原话，经去重和业务复核后冻结 120 条正式金标：

| 预期状态 | 建议数量 | 设计重点 |
|---|---:|---|
| ANSWER | 70 | 单条款、多条款、跨制度、条件例外、职责、流程、时限、数值、表格和计算 |
| INSUFFICIENT_EVIDENCE | 30 | 制度未规定、缺少必要条件、库外事项、过期或隔离资料、只能由人工裁量的问题 |
| CONFLICT | 20 | 只收录经业务专家确认的真实冲突、新旧制度覆盖或适用范围差异；每个立场都必须有证据 |

难度建议为简单 30、中等 50、困难 40。每份有效制度至少覆盖 3 题，高频制度按真实咨询量增加；不要机械地给每份制度平均配题。

## 3. 员工如何出题

员工按真实工作语言填写，不需要写成制度原文，也不负责最终金标。

1. 一行只写一个主要问题；确有连续追问时，把前置条件写在“追问或上下文”。
2. 写清人物、事项、时间、金额、地区、岗位等会改变答案的条件。
3. 优先提交自己真实问过、同事常问或容易误解的问题。
4. 可以保留口语、省略、简称和常见错别字，但不能故意写成无法理解的句子。
5. 如果知道相关制度、关键答案点或证据原文，可以填写；不知道就留空，不要猜。
6. 不提交姓名、身份证号、联系方式、账号、案件细节等个人或敏感信息；先完成脱敏。

不建议采用“把制度每一条改写成一个问句”的出题方式。这种题与原文过近，只能证明关键词召回，不能代表员工真实使用效果。

## 4. 专家如何形成金标

业务专家必须核对当前有效制度正文，按问题范围形成金标：

- `ANSWER`：写“必答关键点”和支持每个关键点的证据；同条款中的扩展信息放入“可选补充点”，不能误判为必答。
- `INSUFFICIENT_EVIDENCE`：写清缺少什么，不用相似度高低代替证据充分性判断；可标记最容易误导系统的近似条款。
- `CONFLICT`：写明冲突主题、各立场、适用边界和各自证据。只有一方有证据时不能标成 CONFLICT。
- 证据优先记录制度名称、文号、条款路径、页码和原文。`document_id`、`primary_node_id`、各类 run ID、`evidence_uid` 和 `snapshot_hash` 由系统或研发复核后补齐。
- 冲突题至少由两名业务人员复核；普通题至少由一名非出题人复核。

## 5. 分配与防泄漏规则

1. 先完成金标，再按 `paraphrase_group_id` 分组切分数据。
2. 推荐将合格题按 50% DEV、30% HOLDOUT、20% REGRESSION 种子分配；PERF 从稳定题中另行复制案例 ID，不改动质量分区。
3. HOLDOUT 的标准答案、证据和评分结果只由验收负责人保管，研发只接收汇总指标和失败类型。
4. 同一事实的正式问法、口语问法、错别字问法不能拆到不同分区。
5. 制度版本变化后不直接覆盖旧金标；新建数据集版本并记录适用日期、制度状态和证据快照。

## 6. 人工评分规则

发布判断不使用单一总分替代硬规则。以下任一情况出现即判失败：

- 实际状态与预期状态不一致；
- ANSWER 的关键结论没有证据支撑，或出现制度中没有的具体结论；
- INSUFFICIENT_EVIDENCE 输出猜测性的金额、时限、责任主体或办理结论；
- CONFLICT 未展示至少两个立场，或任一立场缺少支持证据；
- Citation 不能定位到正确制度、Node、页码或证据快照。

其余项目按 0/1/2 评分：0 为错误或缺失，1 为部分满足，2 为完整满足。建议分别报告状态准确率、关键点完整率、引用支撑率、引用完整率、拒答准确率和冲突双边证据完整率。

## 7. 组织流程

1. 测试负责人确定批次、覆盖制度和各部门征集数量。
2. 员工只填写“员工问题征集”页。
3. 业务专家在“专家金标”和“证据标注”页完成复核。
4. 测试负责人去重、设置 `paraphrase_group_id`、分配数据分区并冻结版本。
5. 研发将金标转换为机器可读数据，通过公开问答入口执行，不依赖受控 debug 字段。
6. 人工复核失败项；确认的问题进入 REGRESSION，保留首次失败原因和修复版本。
7. 性能测试单独使用 PERF 清单，待进程内 RAG 暖态测试完成后再确定 SLA、超时提示阈值和并发容量。
